# 非论文写作与措辞精简

本规范负责四类非论文中文写作：**技术方案、组会和项目汇报、博客与长笔记、译后的中文润色**；其中的「删减防御性措辞」与只审不改用法对**中英文稿都适用**。不判断文字是不是 AI 写的。单篇稿件或项目文件夹里有术语表时先读再用，与翻译、论文写作读同一份；项目的 `AGENTS.md` 或用户明确给的规则优先于本文件。

以下任务不归本规范：学术论文正文、开题报告与改稿用 `paper-writing-zh`；项目入口 README 与交接文档用 `project-docs`；对话里给用户的日常工作汇报照全局规则；中英互译用 `translate`（译完再润色中文时用本规范）。

## 长稿协作步骤

写多章节新稿按下面两步走；改写现成草稿或写短稿时跳过对齐与第 2 步，直接起草。

1. **对齐与起草**：动笔前对齐读者、决策用途与各节提纲详略，缺关键事实或边界先问清；起草时每节每段结论先行，前提、代价与风险紧跟其后，同一术语全文一致。
2. **零背景读者盲测（重要长稿按需）**：跨团队方案或重大汇报写完后，**由主会话派发**（被派出的写手不再往下派子代理）一个不带起草上下文的代理只读成稿，回答“核心结论是什么、有哪些前置条件与风险、哪一处有歧义或看不懂”，只修真实缺口。

## 与论文不同的句法与层次

通用中文句法（主语明确、不夹长括号、一句话只讲一个意思）按全局沟通规则执行；下面只写与学术论文不同的地方：

- **直接写出动作主体与责任人**：方案、汇报和计划可直接用“我们、本方案、某模块、某负责人”做主语，排期、接口与验收条件写明归属，不用无主句把责任悬空。
- **列表、对比表与图表从简**：要点列表写完整陈述句、短段不硬加多层小标题；对比表只列现象、效果和代价，图表与配置已有的内容不复述，正文只写结论、原因或边界。

## 破翻译腔与空话

以下规则自中文论文句子规范的“的、被和进行”与“套话和翻译腔”精简而来，出现时看它有没有提供信息，没有就删或改成具体事实：

- **“的”字链**：名词前连用三个以上“的”或定语长到迟迟见不到中心词时，拆开重写结构（如把长修饰语挪到中心词后作分句），不靠硬删“的”字。
- **“进行 / 加以 / 予以”加动词**：“对参数进行了校准”“对接口加以改造”直接写成“校准了参数”“改造了接口”；后面跟带数量的名词（如“进行了三轮压测”）不必改。
- **“被”字句**：做事的一方明确、改成主动更顺时用主动；施事不重要或未知时（如“旧缓存已被清理”）保留。
- **名词空转**：“实现了吞吐量的提升”写成“提高了吞吐量”；“具有部署简单的特点”写成“部署简单”。
- **无信息套话与空泛修饰**：“具有重要意义 / 起着至关重要的作用”改成具体后果或用途；“显著 / 有效 / 大幅 / 明显”后面必须跟数据或比较对象（如“耗时缩短了 40%”保留）；“不仅……更是…… / 不是……而是……”两半都有实质信息才留；没有独立信息的“随着……的发展 / 在……的背景下”直接删；“值得注意的是 / 综上所述 / 总的来说”多数直接删（段末真正归纳了共性时留“综上”，确有先后顺序时留“首先、其次”）；“高效精准、稳定可靠”这类四字词连用换成能检查的事实；“在……层面 / 从……维度 / 在……框架下”连排贴标签时，按真实性质换回“模块、阶段、工况、方面”，或直接让具体对象做主语。

## 删减防御性措辞（中英文通用）

按一句话“对读者的决策有没有用”来判断去留，不列禁词表，也不按关键词一刀切。边界拿不准时读 [examples.md](references/examples.md)。

- 删掉只为自证勤勉、预先应对批评、道歉，或声明“本文不打算做什么”的句子。
- 层层叠加的保留（may perhaps potentially、“可能在一定程度上或许”）压成一个与证据相符的限定。
- 范围用正面写法说明覆盖什么；排除项只在会影响归属、验收或责任时保留。
- 改变法律、安全、财务、方法、合同或范围判断的限制必须保留，放在它所限定的结论旁边。
- 同一个短语在不同语境里可能是废话也可能必要，按它对读者决策的作用判断，不按关键词。

## 不能改变的内容与输出

- **不能改变的内容**：不增删事实、数字、来源和责任人；不把不确定写成确定，不把相关写成因果；**删掉保留措辞不等于提高结论强度**。原文已经直接、准确时原样返回。
- **直接起草或改写**：用户给了文本或写作要求、没说只做审查时，直接输出成稿（长文写入目标文件），用户要求说明时再附修改说明；拿不准的事实、术语或口径在交付时单独列出，不写进正文。
- **只审查不改写**：用户要求审查时，不重写全文，逐条给出原句、问题和最小改法；没有值得改的就直说。
