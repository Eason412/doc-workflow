# 非论文写作与措辞精简

本规范负责四类非论文中文写作：**技术方案、正式项目与多仓汇报、博客与长笔记、译后的中文润色**；其中的「删减防御性措辞」与只审不改用法对**中英文稿都适用**。专注表达清晰度与信息密度，跳过是否为 AI 生成的判定。单篇稿件或项目文件夹里有术语表时先读再用，与翻译、论文写作读同一份；项目的 `AGENTS.md` 或用户明确给的规则优先于本文件。

学术论文正文、开题报告与改稿使用 `paper-writing-zh`，项目入口 README 与交接文档使用 `project-docs`，中英互译使用 `translate`（译完再润色中文时归本规范）。对话里的日常简短工作汇报照全局规则执行；多仓阶段汇总、正式项目汇报、技术方案与更新公告归本规范。

## 长稿协作步骤

写多章节新稿按下面两步走；改写现成草稿或写短稿时跳过对齐与第 2 步，直接起草。

1. **对齐与起草**：动笔前对齐读者、决策用途与各节提纲详略，缺关键事实或边界先问清；起草时每节每段结论先行，前提、代价与风险紧跟其后，同一术语全文一致。
2. **零背景读者盲测（重要长稿按需）**：跨团队方案或重大汇报写完后，**由主会话派发**（被派出的写手不再往下派子代理）一个不带起草上下文的代理只读成稿，回答“核心结论是什么、有哪些前置条件与风险、哪一处有歧义或看不懂”，只修真实缺口。

## 与论文不同的句法与层次

通用中文句法（主语明确、不夹长括号、一句话只讲一个意思）按全局沟通规则执行；下面只写与学术论文不同的地方：

- **直接写出动作主体与责任人**：方案、汇报和计划优先用具体主体（本方案、某模块、某负责人）明确责任归属，仅在团队合写正式文档时按需使用“我们”，不与日常对话汇报冲突；排期、接口与验收条件写明归属，替代悬空责任的无主句。
- **列表、对比表与图表从简**：要点列表写完整陈述句，短段保持单层自然段落；对比表只列现象、效果和代价，跳过图表与配置已有的内容，正文只写结论、原因或边界。

## 正式稿与表格

- **正式稿与多仓汇总**：发给别人的方案、汇报和调研总结用名词化的现代书面语，把临时口语改写为明确表述（如“还没做需要注意的”写成“后期目标”）；多条事实按 `1. 2. 3.` 分点，独立成句的每条用句号收尾，每条写明原因并结合现象给出改进方向。多仓正式汇总按仓库分节，小标题用“增加功能”“未完成”等短语，“未完成”只列推进中或当前待办，空小节直接省略；汇报改动紧跟动作说明目的，选用自然动宾表达替代“该功能用于”一类生硬句式。
- **更新公告与变更日志**：面向使用者的版本更新公告和变更日志采用简洁、平实的现代书面语，直述新增功能、体验改进与问题修复，将口语和内部实现缩写改写为普通用户看得懂的表达。
- **交付格式**：默认交付 Markdown，仅在用户明确要求时转换 docx 等格式；需要打包外发时，把配图放进同一目录，并确认文中图片能正常显示。
- **表格**：表头写 2–5 字的属性名，带单位时写成 `耗时 (s)`，保持单行不折行且省略整句或括号解释；首列写对象名称；同一列句式一致，一格只写一件事。示例见 [examples.md](references/examples.md)。

## 破翻译腔与空话

以下规则自中文论文句子规范的“的、被和进行”与“套话和翻译腔”精简而来，出现时看它有没有提供信息，没有就删或改成具体事实：

- **“的”字链**：名词前连用三个以上“的”或定语长到迟迟见不到中心词时，拆开重写结构（如把长修饰语挪到中心词后作分句），重排定语位置以保持句子主干清晰。
- **“进行 / 加以 / 予以”加动词**：“对参数进行了校准”“对接口加以改造”直接写成“校准了参数”“改造了接口”；后面跟带数量的名词（如“进行了三轮压测”）原样保留。
- **“被”字句**：做事的一方明确、改成主动更顺时用主动；施事不重要或未知时（如“旧缓存已被清理”）保留。
- **名词空转**：“实现了吞吐量的提升”写成“提高了吞吐量”；“具有部署简单的特点”写成“部署简单”。
- **无信息套话与空泛修饰**：“具有重要意义 / 起着至关重要的作用”改成具体后果或用途；“显著 / 有效 / 大幅 / 明显”后面必须跟数据或比较对象（如“耗时缩短了 40%”保留）；“不仅……更是…… / 不是……而是……”两半都有实质信息才留；没有独立信息的“随着……的发展 / 在……的背景下”直接删；“值得注意的是 / 综上所述 / 总的来说”多数直接删（段末真正归纳了共性时留“综上”，确有先后顺序时留“首先、其次”）；“高效精准、稳定可靠”这类四字词连用换成能检查的事实；“在……层面 / 从……维度 / 在……框架下”连排贴标签时，按真实性质换回“模块、阶段、工况、方面”，或直接让具体对象做主语。

## 删减防御性措辞（中英文通用）

按一句话“对读者的决策有没有用”来判断去留，结合语境逐句判断，替代静态禁词表和关键词一刀切。边界拿不准时读 [examples.md](references/examples.md)。

- 删掉只为自证勤勉、预先应对批评、道歉，或声明“本文不打算做什么”的句子。
- 层层叠加的保留（may perhaps potentially、“可能在一定程度上或许”）压成一个与证据相符的限定。
- 范围用正面写法说明覆盖什么；排除项只在会影响归属、验收或责任时保留。
- 改变法律、安全、财务、方法、合同或范围判断的限制必须保留，放在它所限定的结论旁边。
- 同一个短语在不同语境里可能是废话也可能必要，按对读者决策的实际作用判断取舍，而非按固定关键词判断。

## 不能改变的内容与输出

- **不能改变的内容**：不增删事实、数字、来源和责任人；不把不确定写成确定，不把相关写成因果；**删掉保留措辞不等于提高结论强度**。原文已经直接、准确时原样返回。
- **直接起草或改写**：用户给了文本或写作要求、没说只做审查时，直接输出成稿（长文写入目标文件），用户要求说明时再附修改说明；拿不准的事实、术语或口径在交付时单独列出并标明待确认，避免写入正文。
- **只审查不改写**：用户要求审查时，保持原文不动，逐条给出原句、问题和最小改法；全文已达标时直接说明。
